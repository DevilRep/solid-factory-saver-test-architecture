# Challenges and examples of solutions

This is a list of use cases, challenges and solutions that help to understand how this architecture works

## Use cases
1. Only reading the data from storage (the simplest code)
2. Code lifecycle: adding a new separate field
3. Updating the data in storage (usage of a [saver](/docs/terms.md#saver))
4. Code lifecycle: adding a new related field
5. Saving changelogs while updating the data in the store
6. Transactional updating
7. Checking access restrictions before reading the data
